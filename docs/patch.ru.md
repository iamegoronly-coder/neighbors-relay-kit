Патч меняет реализацию стандартного реле. Формат событий, подписи и клиентский протокол остаются прежними. При смене основы upstream заново проверяйте и тестируйте патч.

## Изменения

- **Точный предел соединений.** `relay.maxConnections` соблюдается в единственном WebSocket-цикле strfry; лишнее соединение закрывается кодом 1013. Несколько процессов с `REUSE_PORT` не имеют общего глобального лимита. `unhealthy_request_count` в Caddy учитывает всю жизнь запроса, включая upgrade, и обычно раньше отвечает 503; окончательный предел обеспечивает реле, в том числе при одновременных рукопожатиях.
- **Проверка срока при чтении.** Начальная выдача пропускает истёкшие NIP-40, эфемерные и слишком старые события **до** подсчёта `limit`; живые подписки проверяют срок до постановки в очередь. Отправленное до истечения событие может прийти позже по сети, поэтому клиенты тоже обязаны проверять срок.
- **Монотонная последовательность.** Сырая таблица LMDB `EventSequence` хранит одну монотонную величину: записывается в той же транзакции, что событие, и сохраняется до удалений, включая первый запуск базы без этой таблицы. В ней нет текстов, ключей клиентов, тегов или ID событий. Чтение последнего внутреннего номера учитывает этот максимум даже при пустой таблице событий; удаление последней записи больше не сбрасывает последовательность, необходимую живым подпискам.

## Сборка

`scripts/build-strfry.sh` выполняет это на Ubuntu 24.04. Вручную — в checkout закреплённого коммита с инициализированными подмодулями и выполненным `make setup-golpe`:

```sh
git apply --check /path/to/strfry-neighbors.patch
git apply /path/to/strfry-neighbors.patch
make -j1 CXXFLAGS='-std=c++20 -O2 -g0 -Wall -fPIC -DDOCOPT_HEADER_ONLY'
```

`git apply --reverse --check` подтверждает применение патча; `scripts/install.sh` требует эту проверку. На маленьком VPS собирайте одним заданием с низким приоритетом и достаточной памятью: с debug-информацией расход превышал 1,5 ГиБ, с `-g0` работает бюджет 2,5 ГиБ. Лимит работающего реле 512 МиБ не меняется.

## Проверки перед установкой

```sh
python3 tests/test_integration.py --binary /path/to/patched/strfry
python3 tests/test_integration.py --binary /path/to/patched/strfry --capacity 100 --caddy
```

Они используют временную LMDB и loopback-порты и никогда не читают рабочую базу.

## Совместимость базы и откат

Формат событий и индексов сохраняется, добавляется таблица последовательности. Не удаляйте её при работающем реле; никогда не запускайте старый и исправленный бинарники на одной базе: старый не знает сохранённого максимума.

Откатывайте бинарник только при остановленных реле и prune-таймере. Возврат к upstream возвращает ограничения: нет проверки срока при чтении, удаление новейшего события небезопасно для живых подписок. До решения оставьте prune-таймер выключенным и не называйте старую сборку эквивалентной. Не экспортируйте переписку для обычного резервного копирования конфигурации.
