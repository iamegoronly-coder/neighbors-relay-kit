# Простая установка на чистый VPS

[English](quickstart.md) · [Русский](quickstart.ru.md) · [Deutsch](quickstart.de.md)

Мастер `setup.sh` объединяет установку зависимостей, Caddy, реле, таймеров и проверку HTTPS.
Внутри — открытые `scripts/setup-relay.py`, `scripts/install.sh` и конфигурация из этого комплекта.
Можно прочитать их до запуска. Клонирование само по себе не делает запускаемый код безопасным;
оно позволяет проверить код и выбрать конкретную версию до выдачи ей прав root.

**Статус:** репозиторий и Release остаются приватными. Эти HTTPS-команды без авторизации подготовлены для будущей публикации; сейчас без доступа к репозиторию они завершатся ошибкой (обычно HTTP 404). Они не меняют приватность. `v0.1.0-test.6` — тестовый выпуск, а не рекомендация для рабочего сервера.

**Проверки:** test.1 скачан из приватного Release, проверен по SHA-256 и установлен на чистый VPS с Ubuntu 24.04; внешние проверки TLS и WebSocket прошли. Test.6 включает лимит события 60 KiB, очистку только по индексу возраста, тайм-аут smoke-проверки 180 секунд и хранение обычных событий 26 ч. Содержимое test.6 установлено на чистый VPS с Ubuntu 24.04 22 октября 2026 через `install.conf` и `sudo sh install.sh` (бинарный режим, AUTH включён); внешний гибридный TLS, NIP-11 и подключение с устройства прошли, см. [запись (EN)](test-release-test6-2026-10-22.md). Локальные контейнерные тесты не заменяют проверку настоящих systemd/TLS. Экран «Реле» уже есть в main приложения, но ещё не вышел в сборке; AUTH по умолчанию выключен. Test.6 содержит опциональный `--auth`, требующий совместимого клиента. См. раздел README об аутентификации.


## Выбор языка

При запуске `sudo sh setup.sh` интерактивный мастер сначала предлагает язык. В остальных случаях используются `LC_ALL`, `LC_MESSAGES`, затем `LANG`, по умолчанию — английский. Язык можно явно задать: `sudo sh setup.sh --lang ru` (или `en` / `de`); это действует и для `--help`, `--plan`, `--check`. Системные утилиты установки и сборки могут выводить собственные сообщения.

## До запуска

- Чистый Ubuntu 24.04 x86_64 с systemd, sudo/root и синхронизированными часами NTP.
- Для готового бинарника: 1 vCPU, около 1 ГиБ RAM, минимум 4 ГиБ свободно на разделе `/var/lib`.
- Для сборки на VPS: минимум 2,5 ГиБ RAM + swap и 6 ГиБ свободно на разделах `/var/lib` и `/opt`
  (если это один раздел, достаточно 6 ГиБ на нём). Мастер сам swap не создаёт.
- Домен с правильными A/AAAA-записями, доступные извне TCP 80/443. Не добавляйте AAAA, если
  IPv6 сервера не работает. Порт 7777 остаётся на loopback; открывать его наружу не нужно.
- Доступ к репозиториям Ubuntu, официальному репозиторию Caddy и центру выдачи сертификатов;
  для сборки — также GitHub и исходникам зависимостей. Комплект не является офлайн-установщиком.

Мастер показывает разрешённые DNS-адреса, но не доказывает, что они принадлежат этому серверу.
Проверьте их в панели хостинга. Наличие старого Caddy, реле, его файлов или занятых портов
80/443/7777 остановит мастер до установки. Для действующего сервера используйте
[ручные шаги](deployment.ru.md), а не удаляйте конфигурацию ради обхода проверки.

## Две команды после публичного выпуска

**Статус:** репозиторий и Release остаются приватными. Эти HTTPS-команды без авторизации подготовлены для будущей публикации; сейчас без доступа к репозиторию они завершатся ошибкой (обычно HTTP 404). Они не меняют приватность. `v0.1.0-test.6` — тестовый выпуск, а не рекомендация для рабочего сервера.

Для **чистого VPS с Ubuntu 24.04 x86_64**, systemd и синхронизацией NTP. Заранее направьте домен на VPS и откройте TCP 80/443. Для готового файла нужно около 1 ГиБ RAM и минимум 4 ГиБ свободно на `/var/lib`.

Нужны `curl`, `ca-certificates`, `tar`, `sha256sum`, Python 3 и sudo/root; для исходников также Git. Если инструменты скачивания/клонирования отсутствуют, установите их один раз:

```sh
sudo apt-get update && sudo apt-get -o DPkg::Lock::Timeout=600 install -y ca-certificates curl git
```

Если вы вошли под root, команды можно выполнять без `sudo`.

1. Скачайте архив закреплённой версии в новый временный каталог:

```sh
relay_work=$(mktemp -d -t neighbors-relay.XXXXXXXX) &&
curl --fail --show-error --location --proto '=https' --proto-redir '=https' \
  --output "$relay_work/neighbors-relay-v0.1.0-test.6.tar.gz" \
  https://github.com/iamegoronly-coder/neighbors-relay-kit/releases/download/v0.1.0-test.6/neighbors-relay-v0.1.0-test.6.tar.gz
```

2. В той же SSH-сессии проверьте закреплённую сумму, затем распакуйте архив и запустите мастер:

```sh
(cd "${relay_work:?Run the download command first}" &&
  printf '%s  %s\n' 'COPY_SHA256_FROM_TEST_6_RELEASE_NOTES' 'neighbors-relay-v0.1.0-test.6.tar.gz' | sha256sum --check - &&
  tar -xzf neighbors-relay-v0.1.0-test.6.tar.gz &&
  cd neighbors-relay && sudo sh setup.sh)
```

Мастер спросит язык, домен и способ установки, затем покажет план для подтверждения. Для готового файла выберите **1**. После публикации GitHub CLI и токен не нужны. Архив остаётся в `$relay_work`; при ошибке HTTP или несовпадении суммы сначала устраните причину. Проверенные распакованные скрипты можно изучить до запуска `sudo sh setup.sh`. Хеш закреплён в инструкции, а не берётся только из соседнего скачанного файла; это не цифровая подпись выпуска.

### Клонирование и сборка исходников

После публикации можно клонировать тот же конкретный тег по HTTPS и выбрать сборку. Сейчас приватный репозиторий по-прежнему требует доступа. Используйте новый каталог; существующее реле мастер не заменяет.

```sh
git clone --branch v0.1.0-test.6 --single-branch \
  https://github.com/iamegoronly-coder/neighbors-relay-kit.git neighbors-relay-source
```

```sh
(cd neighbors-relay-source && sudo sh setup.sh --mode source)
```

В режиме source мастер скачает закреплённые исходники и соберёт реле вместо использования готового бинарника. Нужно минимум 2,5 ГиБ RAM + swap и 6 ГиБ свободно на `/var/lib` и `/opt` (6 ГиБ всего, если это один раздел). Обычная сборка средствами Ubuntu может дать другой хеш; для побайтного сравнения используйте каноническую Docker-сборку.

## Локальный комплект с готовым файлом

Перенесите архив и его `.sha256` на свой VPS. В каталоге с ними проверьте целостность и распакуйте
в пустой рабочий каталог (не поверх другой копии):

```sh
sha256sum -c neighbors-relay-v0.1.0-test.6.tar.gz.sha256
tar -xzf neighbors-relay-v0.1.0-test.6.tar.gz
cd neighbors-relay
sudo sh setup.sh
```

Введите домен, выберите **1 — готовый файл** и прочитайте план. Подтверждение — `да`, `yes` или `ja`.
Мастер проверит SHA-256 и архитектуру бинарника, установит Caddy 2.11.7 из его
[официального APT-репозитория](https://caddyserver.com/docs/install#debian-ubuntu-raspbian),
проверит закреплённый отпечаток ключа репозитория до добавления доверия,
закрепит версию через `apt-mark hold`, установит реле, включит таймеры и настроит сертификат.
В конце появится адрес `wss://ваш-домен/relay`.

Бинарник лежит в `payload/strfry`, соответствующие исходники с подмодулями — в
`payload/source.tar.gz`; рядом находятся GPL-лицензия, патч, параметры сборки и суммы.
Метаданные ожидаемого кандидата — `release/local-candidate.json`.
Сумма рядом с архивом проверяет целостность, но не удостоверяет автора, если подменили оба файла.
Этот локальный комплект пока не подписан.

Только предварительная проверка и план, без установки:

```sh
sudo sh setup.sh --mode binary --domain relay.example.org --plan
```

Явно выбранный файл, в том числе полученный собственной канонической сборкой:

```sh
sudo sh setup.sh --mode binary --domain relay.example.org \
  --binary /path/to/strfry --sha256 "$EXPECTED_SHA256"
```

`EXPECTED_SHA256` нужно получить из проверенной сборки или доверенного описания выпуска.
Для автоматизации после просмотра плана можно добавить `--yes`. Без него неинтерактивная
установка не начинается. `--tls-timeout 600` увеличивает ожидание HTTPS с 180 до 600 секунд.


## Файл значений

Вместо ответов мастеру заполните `install.conf` рядом с `setup.sh` и запустите `sudo sh install.sh`. Ключи: `DOMAIN` (обязателен), `AUTH` (`yes` по умолчанию: конверт читает только то приложение, которому он адресован; `no` оставляет чтение публичным), `LANGUAGE` (`en`, `ru`, `de`), `NAME` и `CONTACT` (необязательные имя и контакт для NIP-11), `MODE` (`binary` или `source`) и `TLS_TIMEOUT`. Обёртка передаёт `setup.sh` параметры `--config install.conf --yes`; дополнительные параметры важнее файла. Предварительные проверки, план, блокировка и правила восстановления те же, что у мастера. Итоговая сводка называет адрес реле, место в приложении, куда его ввести, смысл выбранной авторизации, `--check` и путь к сохранённому состоянию; `--check` печатает её снова в любой момент.

## После установки или при ошибке

Повторная проверка без установки и изменения конфигурации:

```sh
sudo sh setup.sh --check
```

Она проверяет службы, health, локальный HTTPS с проверкой имени и доверия к сертификату,
NIP-11 и ответ 404 для `/metrics`. Домен берётся из сохранённого состояния; можно передать
`--domain` явно. Проверка не публикует событий и не проверяет WebSocket-доставку сообщений.

Если сертификат ещё не готов, исправьте DNS/порты и повторите `--check`. Это не переустанавливает
пакеты и не обновляет сохранённую фазу установки. История последней фазы и хеш находятся в
`/var/lib/neighbors-relay-setup/state.json`. Для диагностики:

```sh
systemctl status caddy strfry --no-pager
journalctl -u caddy -n 50 --no-pager
/usr/local/libexec/strfry-health
```

Если ошибка произошла раньше, чем установлены службы, `--check` их не достроит. Сохраните вывод
и завершите необходимые шаги вручную после выяснения причины. Автоматического продолжения
частичной установки и отката пакетов пока нет. Не удаляйте базу или файл состояния, чтобы
заставить мастер пройти повторно. При неудачной перезагрузке Caddy мастер восстанавливает
его исходный файл из пакета; существующую пользовательскую конфигурацию он не заменяет.

Из другой машины выполните внешнюю проверку TLS (нужен OpenSSL 3.5+):

```sh
OPENSSL=/path/to/openssl sh scripts/check-pq-tls.sh relay.example.org
```

Именно внешнее рукопожатие подтверждает доступность и `X25519MLKEM768`; успешная установка
версии Caddy этого не доказывает. Для проверки доставки есть [smoke-тест и очистка](../README.ru.md#ручная-установка).
Гибридный TLS не делает сквозное шифрование сообщений постквантовым.

Мастер не меняет SSH, firewall и DNS, не создаёт swap и не перезагружает сервер. Закреплённый
Caddy требует плановых обновлений оператором: [обновление и откат](caddy.ru.md#обновление).

## Собрать локальный архив

На машине подготовки, где есть `out/v0.1.0-test.6` (Python 3.11+):

```sh
python3 scripts/package-local.py --output out/neighbors-relay-local.tar.gz
```

Архиватор сверяет бинарник, исходники, патч, набор инструментов и манифест, включает только
перечисленные в коде каталоги комплекта и файлы кандидата. Он не включает `.git`, остальные
`out`, `.env` в корне и кэши Python; символьные ссылки отклоняет. Не храните секреты внутри
каталогов документации, конфигурации или скриптов: их содержимое входит в комплект.
Существующий архив не перезаписывается. Никакие файлы не загружаются на внешние сервисы.

## Перед публичным запуском

Перед публичным запуском выберите и проверьте окончательный выпуск, одновременно обновите тег, имя архива и закреплённый SHA-256 во всех трёх README и quickstart, проверьте оба пути на чистых VPS. После публикации проверьте анонимное скачивание с машины без учётных данных GitHub. Не заменяйте файл существующего выпуска ради совпадения со старой суммой. Изменение приватности требует отдельного решения; эти инструкции не означают разрешение на публикацию.
