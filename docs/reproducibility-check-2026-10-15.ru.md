# Проверка воспроизводимости: 15 октября 2026

[English](reproducibility-check-2026-10-15.md) · [Русский](reproducibility-check-2026-10-15.ru.md) · [Deutsch](reproducibility-check-2026-10-15.de.md)

Две чистые сборки реле в отдельных Docker build stages на одном Mac ARM64
(`--platform linux/amd64`) дали **побайтно одинаковые исполняемые файлы**.
Этапы компиляции запускались отдельно с `BUILD_RUN=first` и `BUILD_RUN=second`,
без переноса объектных файлов или готового реле между ними. Среда компилятора была общей
по закреплённым версиям пакетов. Это локальная проверка, не независимый аудит на двух VPS.

- Базовый commit strfry: `4cd3cf64850caf47dda46c2a2abbbf3525a64d10`.
- Архитектура: Linux x86_64; Ubuntu 24.04.
- Компилятор: GCC 13.3.0 (`13.3.0-6ubuntu2~24.04.1`).
- SHA-256 обоих бинарников: `be71c12620a1eee1fcc436b9ce0dfa0ce7cb69f2747a5cd00062b811b1c3a18d`.
- Размер каждого: 3101064 байт.
- Результат `compare-binaries.py`: `IDENTICAL: every byte matches`.

## Что проверено

- Все существующие быстрые проверки комплекта и 7 новых тестов проверки/сравнения бинарников.
- Неверный хеш отклоняется до создания файлов и запуска служб реле; готовый файл
  устанавливается без изменения байтов; существующая служба не перезаписывается.
  Этот тест выполнялся в одноразовом Ubuntu-контейнере с явными заглушками Caddy,
  systemd и проверки здоровья, поэтому сам по себе не подтверждает загрузку systemd.
- **Установленный** канонический бинарник прошёл интеграционные тесты с реальной временной
  LMDB и WebSocket на loopback, при ограничении контейнера 1 CPU / 1 ГиБ RAM:
  предел соединений, фильтрация истечения срока до LIMIT, доставка после трёх полных
  очисток базы, освобождение слотов, некорректный JSON и медленный получатель.
- Контрольные суммы файлов обоих выходных комплектов и наличие исходников с подмодулями
  в архивах проверены. Побайтное совпадение заявляется для бинарника; служебные Git-данные
  в архивах исходников могут различаться между клонированиями.

## Что ещё нужно до публичного выпуска

Повторить сборку на независимой машине, проверить оба пути на чистых VPS с настоящим
systemd/Caddy, оформить GitHub Release и аутентификацию выпуска. Архивирование пакетов
компилятора или закреплённый снимок Ubuntu нужны для долгосрочной воспроизводимости.

Этот канонический бинарник не устанавливался на тестовый VPS или рабочие реле.
Предыдущая проверенная установка тестового VPS использует обычную сборку с другим хешем.
Совпадение файлов не доказывает отсутствие уязвимостей или конфигурацию чужого сервера.
